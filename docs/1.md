建议分两层修复：先做低风险修复，再完善命中测试模型。

### 一、低风险修复

#### 1. 始终同步实际 Ribbon 标题栏高度

在 `SARibbonMainWindow::setRibbonBar()` 中保留初始化同步，并监听 `SARibbonBar::titleBarHeightChanged`：

```cpp
connect(ribbon,
        &SARibbonBar::titleBarHeightChanged,
        this,
        [this](int, int newHeight) {
#if !SARIBBON_USE_3RDPARTY_FRAMELESSHELPER
            if (auto helper = d_ptr->mFramelessHelper) {
                helper->setTitleHeight(newHeight);
            }
#endif
            if (auto sysBar = d_ptr->mWindowButtonGroup) {
                sysBar->setWindowTitleHeight(newHeight);
            }
        });
```

这样用户调用：

```cpp
ribbonBar()->setTitleBarHeight(40);
```

后，无边框辅助类不会继续使用旧的 `30`。

建议修改：

- `src/SARibbonBar/SARibbonMainWindow.cpp`
- 必要时在 `SARibbonMainWindow.h` 增加私有槽函数，避免复杂 lambda。

#### 2. 移除双击判断中的重复 DPI 缩放

当前逻辑：

```cpp
qreal dpiScale = SAFramelessHelper::getScreenDpiScale(m_pWidget);
int scaledTitleHeight = s_titleHeight * dpiScale;
bool titlePressed = eventPosY(event) < scaledTitleHeight;
```

应改为：

```cpp
const int titleHeight = SAPrivateFramelessCursorPosCalculator::s_titleHeight;
const bool titlePressed = SA::compat::eventPosY(event) < titleHeight;
```

原因是 Qt 的 QWidget 几何尺寸和鼠标事件坐标通常已经是逻辑像素，标题栏高度再乘 `devicePixelRatio()` 会造成高 DPI 下命中区域扩大。

同样需要检查 `handleMousePressEvent()` 中的标题栏判断，保持坐标单位一致。

---

### 二、基于实际布局的命中测试

不要只依赖 `eventPosY < titleHeight`，建议增加标题栏控件和实际坐标判断。

#### 1. 给 `SAFramelessHelper` 增加标题栏控件

例如：

```cpp
void setTitleBarWidget(QWidget* titleBarWidget);
```

内部保存标题栏控件指针：

```cpp
QPointer<QWidget> m_titleBarWidget;
```

命中时使用全局坐标转换：

```cpp
bool SAPrivateFramelessWidgetData::isTitleBarPosition(
    const QPoint& globalPos) const
{
    if (!m_titleBarWidget) {
        return false;
    }

    const QPoint localPos =
        m_titleBarWidget->mapFromGlobal(globalPos);

    const QRect titleRect(
        0,
        0,
        m_titleBarWidget->width(),
        m_titleHeight);

    return titleRect.contains(localPos);
}
```

在 `SARibbonMainWindow::setRibbonBar()` 中：

```cpp
mFramelessHelper->setTitleBarWidget(ribbon);
```

这里传入 `ribbon` 仅用于全局坐标映射；命中区域仍严格限制在其顶部的
`SARibbonBar::titleBarHeight()` 逻辑像素内。不能使用 `ribbon->height()`，否则 Tab 栏和面板区域的双击也会触发最大化/还原。

#### 2. 保留可交互子控件的事件处理

最大化、最小化、关闭按钮以及用户自定义按钮不能被标题栏拖动逻辑抢占。

不应将以下控件的事件转发给内置无边框辅助类：

- `SARibbonSystemButtonBar`
- 最小化、最大化、关闭按钮
- `SARibbonApplicationButton`
- `SARibbonQuickAccessBar`
- `SARibbonTabBar` 中实际可点击的 Tab
- 用户通过接口注册的自定义控件

这些控件应继续由自身处理；仅 Ribbon 自身接收的空白标题栏区域进入最大化/还原逻辑。这样不会因子控件局部坐标或事件重复分发而触发错误的窗口操作。

---

### 三、推荐的最终结构

```text
鼠标双击事件
    ↓
获取全局坐标
    ↓
判断是否位于实际 Ribbon 标题栏
    ↓
事件是否由可交互子控件接收
    ├─ 是：交给子控件
    └─ 否：执行最大化/还原
```

### 四、回归测试

至少覆盖：

- 标题栏高度为默认值、40、60；
- 100%、125%、150%、200% DPI；
- 窗口从主屏拖到副屏；
- 普通状态双击最大化；
- 最大化状态双击还原；
- 标题栏空白区域；
- Tab、快速访问栏、应用按钮区域；
- 最大化按钮仍可稳定点击；
- 多个 `SARibbonMainWindow` 同时存在。

优先级建议：

1. 修复高度动态同步；
2. 移除重复 DPI 缩放；
3. 改为全局坐标和实际 Ribbon 标题栏高度命中；
4. 补充交互控件和自动化回归测试。
